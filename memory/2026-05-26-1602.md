## 一、代码结构分析

xsched 是一个 OSDI'25 论文的 XPU 指令调度框架，核心目录如下：

| 目录 | 作用 |
|------|------|
| `platforms/hip/` | **HIP 平台适配**（海光 DCU 用这一层） |
| `platforms/hip/hal/` | XAL 硬件适配层，封装 `HipQueue` / `HipCommand`，实现 Level-1 抢占 |
| `platforms/hip/shim/` | XShim 拦截层，透明劫持 `libamdhip64.so` 的 API 调用，转发到 XQueue |
| `preempt/` | XPreempt 抢占模块，管理 XQueue 生命周期、上报事件给调度器 |
| `sched/` | 调度策略（HPF/UP/PUP/KEDF/LAX/AWF/CFS/MLFQ 等） |
| `service/server/` | **xserver** — 全局调度器守护进程 |
| `service/cli/` | **xcli** — 命令行监控/控制工具 |
| `protocol/` | 环境变量配置、IPC 协议定义 |
| `include/` | 公共头文件 + Python 绑定 (`xsched.py`) |

**调度流程**: 应用程序 → XShim 劫持 HIP API → 封装为 XQueue → Preempt Agent 上报事件 → xserver 全局调度 → 下发操作 → Preempt Agent 执行 Suspend/Resume

## 二、海光 DCU 编译步骤

海光 DCU 走 **ROCm/HIP** 路线，`xsched` 已原生支持 `platforms/hip`。

### 2.1 前置依赖

```bash
# 1. 确保 ROCm/HIP 运行时已安装
hipcc --version        # 验证 hipcc 可用
rocminfo               # 验证 DCU 设备可见
ls /opt/rocm/lib/libamdhip64.so  # 确认 HIP 驱动库位置

# 2. 安装编译依赖
sudo apt-get install -y cmake build-essential g++ git

# 3. 克隆代码并初始化子模块
cd /mnt/d/code/xsched/xsched
git submodule update --init --recursive
```

### 2.2 编译 XSched（HIP 平台）

```bash
cd /mnt/d/code/xsched/xsched

# 方式一：使用 Makefile（推荐）
make hip

# 方式二：手动 CMake 编译
cmake -B build \
    -DCMAKE_BUILD_TYPE=Release \
    -DCMAKE_INSTALL_PREFIX=$(pwd)/output \
    -DSHIM_SOFTLINK=ON \
    -DPLATFORM_HIP=ON
cmake --build build --target install -j$(nproc)
```

编译产物在 `output/` 下：

```
output/
├── bin/
│   ├── xserver          # 全局调度服务
│   └── xcli             # 命令行工具
├── lib/
│   ├── libshimhip.so    # HIP shim 拦截库
│   ├── libamdhip64.so -> libshimhip.so    # 软链接，劫持原始 HIP 库
│   ├── libamdhip64.so.1 -> libshimhip.so
│   ├── libhalhip.so     # HIP 硬件适配层
│   ├── libpreempt.so    # 抢占模块
│   └── libsched.so      # 调度策略库
└── include/
```

## 三、测试步骤

### 3.1 测试场景：透明优先级调度（HPF 策略）

测试原理：两个进程同时跑 DCU 向量加法，高优先级进程被 xsched 优先调度，性能接近独占；低优先级进程被抑制。

#### Step 1：启动全局调度器 (xserver)

```bash
# 终端1 - 启动调度服务
cd output/bin
./xserver HPF 50000
# HPF = Highest Priority First 策略
# 50000 = xcli 连接端口
```

#### Step 2：启动高优先级应用

```bash
# 终端2
cd examples/Linux/1_transparent_sched

export XSCHED_SCHEDULER=GLB
export XSCHED_AUTO_XQUEUE=ON
export XSCHED_AUTO_XQUEUE_PRIORITY=1
export XSCHED_AUTO_XQUEUE_LEVEL=1
export XSCHED_AUTO_XQUEUE_THRESHOLD=16
export XSCHED_AUTO_XQUEUE_BATCH_SIZE=8
export LD_LIBRARY_PATH=/mnt/d/code/xsched/xsched/output/lib:$LD_LIBRARY_PATH

./app
```

#### Step 3：启动低优先级应用

```bash
# 终端3
cd examples/Linux/1_transparent_sched

export XSCHED_SCHEDULER=GLB
export XSCHED_AUTO_XQUEUE=ON
export XSCHED_AUTO_XQUEUE_PRIORITY=0
export XSCHED_AUTO_XQUEUE_LEVEL=1
export XSCHED_AUTO_XQUEUE_THRESHOLD=4
export XSCHED_AUTO_XQUEUE_BATCH_SIZE=2
export LD_LIBRARY_PATH=/mnt/d/code/xsched/xsched/output/lib:$LD_LIBRARY_PATH

./app
```

#### 预期结果

| 进程 | 预期每任务耗时 | 说明 |
|------|---------------|------|
| 高优先级 (P=1) | ~66ms | 接近独占性能 |
| 低优先级 (P=0) | ~180-200ms | 被显著抑制，约 3x 慢 |

#### 对比：不加 xsched 的基线

```bash
# 不加任何环境变量，两个终端同时跑 ./app
# 两个进程平均分配 DCU 资源，耗时都约 130ms（2倍于独占）
```

## 四、环境变量详解

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `XSCHED_SCHEDULER` | GLB | GLB=全局调度, LCL=本地调度, APP=手动管理 |
| `XSCHED_AUTO_XQUEUE` | OFF | ON=创建 hipStream 时自动创建 XQueue |
| `XSCHED_AUTO_XQUEUE_PRIORITY` | 0 | -256~255，越大优先级越高 |
| `XSCHED_AUTO_XQUEUE_LEVEL` | 1 | 抢占级别：1=Block 级, 2=Deactivate, 3=Interrupt |
| `XSCHED_AUTO_XQUEUE_THRESHOLD` | 16 | in-flight 命令数上限，越小抢占越快但开销更大 |
| `XSCHED_AUTO_XQUEUE_BATCH_SIZE` | 8 | 单次 launch 命令数，建议为 threshold 的一半 |

**Level 说明**：海光 DCU 当前代码只实现了 **Level-1（Block 级抢占）**——即等到当前 kernel 执行完才切换。Level-2（Deactivate）和 Level-3（Interrupt）需要硬件支持，在 HIP 平台标记为 `🔘`（未实现）。

## 五、可能遇到的问题及处理

### 5.1 编译问题

```bash
# 如果 hipcc 找不到
export PATH=/opt/rocm/bin:$PATH

# 如果找不到 libamdhip64.so
# 检查 ROCm 安装
ls /opt/rocm/lib/libamdhip64.so*
# 可能版本号是 libamdhip64.so.5 等，需要确认实际路径
```

### 5.2 运行时库加载

```bash
# 确保 shim 库优先加载
# xsched 通过软链接 libamdhip64.so -> libshimhip.so 实现透明劫持
# LD_LIBRARY_PATH 需要把 output/lib 放在最前面
export LD_LIBRARY_PATH=/mnt/d/code/xsched/xsched/output/lib:/opt/rocm/lib:$LD_LIBRARY_PATH

# 验证劫持成功
ldd ./app | grep amdhip64
# 应该显示指向 output/lib/libamdhip64.so（即 libshimhip.so）
```

### 5.3 IPC 通信

```bash
# xserver 使用 IPC 通道与客户端进程通信
# 如果连接失败，检查 /tmp 下是否有 IPC 文件残留
ls /tmp/xsched_*
# 必要时清理
rm -f /tmp/xsched_*
```

### 5.4 调试模式

```bash
# 使用 Debug 编译查看详细日志
make clean
make PLATFORM=hip BUILD_TYPE=Debug
# 日志会输出 XQueue 状态变化、调度决策等
```

## 六、总结

**推荐测试流程**：

```bash
# 1. 编译
make hip

# 2. 启动调度服务
output/bin/xserver HPF 50000 &

# 3. 运行测试（两个终端）
# 终端A：高优先级
LD_LIBRARY_PATH=output/lib ./app_high_priority

# 终端B：低优先级  
LD_LIBRARY_PATH=output/lib ./app_low_priority

# 4. 监控
output/bin/xcli top -f 10
```

核心验证点：**高优先级 app 的 kernel 执行时延应接近独占模式，低优先级 app 明显被抑制**，从而证明 xsched 在海光 DCU 上实现了有效的指令级调度。
